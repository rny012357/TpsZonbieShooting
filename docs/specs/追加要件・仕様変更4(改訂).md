# 1. エリアシステム

従来のWaveシステムは廃止し、Areaシステムへ変更する。

エリア番号は

Area1
Area2
Area3
...

と増加する。

エリア番号が大きくなるほど、

- ゾンビHP
- ゾンビ攻撃力
- ゾンビ出現数

を増加させる。

---

# 2. エリアゲート（Area Gate）

## 概要

各エリアの入口には

**Area Gate（エリアゲート）**

を配置する。

Area Gate は、

**「ここから先は Area○○ です」**

ということをプレイヤーへ視覚的に伝えるための演出オブジェクトである。

敵を閉じ込めたり壁として利用するものではなく、

エリアの切り替わりを分かりやすくすることを目的とする。

---

## 外観

Area Gate は

**透明な平面オブジェクト**

として描画する。

特徴

- 縦方向(y軸方向)に十分な高さを持つ
- 半透明
- 外周はネオン風の発光線
- 内部は薄く着色
- 中央へ Area番号 を表示

例

+------------------------+
|                        |
|       Area 3           |
|                        |
+------------------------+

サイバー空間らしいデザインとする。

---

## ゲーム進行

ゲームの流れは以下とする。

1. プレイヤーが Area Gate を通過する
2. エリア内へ侵入する
3. 配置されたゾンビをすべて撃破する
4. 「AREA ○ CLEAR!」を表示する
5. プレイヤーがさらに前進する
6. 次の Area Gate が現れる

これをゲーム終了まで繰り返す。

---

# 3. ゾンビ配置

各エリア生成時に、

エリア内のランダムなワールド座標へ配置する。

スポーン数は

Area番号が上がるほど増加する。

例

Area1 : 10体

Area2 : 15体

Area3 : 20体

---

# 4. エリア制圧

エリア内の全ゾンビを撃破すると、

画面上部中央へ

AREA ○ CLEAR!

を数秒表示する。

---

# 5. ゾンビAI

スポーン時は待機状態。

以下で起動する。

- プレイヤーが一定距離以内へ入る
- ダメージを受ける

起動後はプレイヤーを追跡する。

---

# 6. ダメージ表示

ダメージ量を数値で表示する。

アニメーション

- 放物線
- 重力
- 徐々に透明化

---

# 7. バフオーブ

ゾンビ撃破時、

バフオーブを1個生成する。

自動取得とする。

演出

- ゾンビ位置から出現
- 放物線でプレイヤーへ飛ぶ
- 発光
- 残像

---

# 8. バフ管理

## バフ種類

均等確率で抽選する。

バフはデータ駆動設計とする。

例

buffs.json

```json
[
  {
    "name":"Attack",
    "type":"attack",
    "values":{
      "C":1,
      "B":2,
      "A":3,
      "S":5,
      "EX":10
    }
  }
]
```

新しいバフ追加時は

JSONへ追加するだけで対応できる構造とする。

---

## レアリティ

Area番号によって抽選重みを変更する。

例

Area1

C >>> B > A > S > EX

Area5

B >>> C > A > S > EX

Area10

A >>> B > S > C > EX

レアリティテーブルもデータ化する。

---

# 9. エリア乱数シード

各エリアは乱数シードを持つ。

例

seed = hash(area_number)

これにより

- 同じエリアは同じ配置を再現できる
- デバッグしやすい
- 将来的にリプレイ機能へ対応しやすい

# 15. 実装上の重要事項

- Waveシステムを完全撤廃する
- Areaシステムへ置き換える
- Area Gate を実装する
- Area Gate は透明な平面オブジェクトとする
- Area Gate はエリア境界を示す演出専用オブジェクトである
- エリアごとに乱数シードを持つ
- バフはJSON等のデータ駆動設計で管理する
- エリアUIは下から上へ番号が増えるレイアウトとする
- スコア・ステータスUIはリアルタイム更新する
